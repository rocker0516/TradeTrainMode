# 約束高頻交易 — 設計討論（僅討論，實作等你說「請實作」）

## 一、目標與前提

- **目標**：約束「高頻交易」（交易次數過多）。
- **前提**：成本線**不與手續費/換手量掛鉤**，避免與主線（log-return）重複懲罰；主線已透過報酬反映手續費，成本線只負責「頻率」維度。

---

## 二、「頻率」怎麼量 — 候選定義

都是**每步**給一個 cost，用「每步平均」做 Lagrangian 約束（與現有 fric 通道一致）。

| 代號 | 本步 cost 定義 | 語意 | 約束到的是什麼 |
|------|----------------|------|----------------|
| **F1** | **I(traded)**：有交易 = 1，無交易 = 0 | 本步有沒有交易 | 每步平均 = 「有交易的步數比例」= 交易頻率（步數維度） |
| **F2** | **α × I(traded)**：有交易 = α（固定常數），無 = 0 | 每筆交易固定成本權重 | 每步平均 ∝ 交易頻率；α 可調敏感度 |
| **F3** | **rolling 視窗內交易次數 / 視窗長度** | 最近 N 步的交易頻率 | 平滑後的頻率；需在 env 維護 rolling count |

**F1** 最單純：cost 就是「本步有沒有交易」0/1，**每步平均 = 有交易步數 / 總步數**，直接對應「交易頻率」。  
**F2** 只是 F1 乘一個常數 α，limit 用「每步平均上限」即可（例如 0.05 = 平均每步最多 0.05，即約 5% 的步數在交易）。  
**F3** 若要做「最近 N 步頻率」需多一點狀態與傳參，可之後再考慮。

---

## 三、與主線的關係（不重複懲罰）

- **主線**：log-return → 手續費多、報酬就低 → 自然懲罰「交易多、手續費多」。
- **本成本線**：只懲罰「**交易發生的次數/頻率**」（有無交易 0/1，或固定權重），**不**乘手續費、不乘 turnover。
- 效果分工：主線管「交易帶來的金錢成本（手續費）」，成本線管「交易次數/頻率」；兩者不重複。

## 四、要你決定的點

1. **頻率定義**：採用 **F1（0/1）**、**F2（α×0/1）** 還是 **F3（rolling）**？  
   - 建議先 **F1**，公式簡單、語意清楚。

2. **通道名稱**：  
   - 維持 **fric**（語意改成「摩擦＝高頻」）  
   - 或改為 **freq** / **trade_freq**（明確表示「交易頻率」）？  
   - 若改名稱，訓練端 Lambda 與 log 的 key 要一併改。

3. **Limit 解讀**：  
   - 例如 `FRIC_COST_LIMIT = 0.05` 表示「每步平均 cost 不超過 0.05」  
   - 在 F1 下 = 「有交易的步數比例 ≤ 5%」→ 直接對應「最多約 5% 的步數在交易」。  
   - 你希望 limit 的數值大概落在哪個範圍（例如 0.01～0.1）？可先給一個你覺得合理的上限，實作時再微調。

4. **僅在有交易時計入，還是每步都計入？**  
   - **每步都計入**：cost = I(traded)，沒交易的那步貢獻 0，有交易貢獻 1 → 平均 = 有交易步數/總步數。  
   - 這樣即可，不需「僅有交易時才計入」；無交易那步本來就是 0。

## 五、小結（等你拍板）

- **目的**：約束高頻交易；成本**不與手續費/換手相關**，不與主線重複懲罰。
- **建議**：本步 cost = **I(traded)**（F1），每步平均 = 交易頻率；limit = 每步平均上限（例如 0.05）。
- **待你決定**：F1/F2/F3、通道是否改名、limit 大概範圍。
